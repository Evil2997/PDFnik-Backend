# TODO-SHARED-MODELS-001 — Вынести общие Pydantic-модели в отдельный пакет

## Описание

Сейчас Pydantic-модели, описывающие формат сообщений между Telegram-ботом и backend-сервисом (контракты для RabbitMQ), *
*дублируются** в двух местах:

* в коде бота;
* в коде backend-а.

Это временное решение (вариант C), принятое для ускорения разработки.
Дальше план — перейти к варианту A: **единый общий Python-пакет с контрактами**, который используют оба микросервиса.

## Цель

* Избежать рассинхронизации схем (когда бот и backend ожидают разные ключи и структуры).
* Иметь **один источник правды** для:

    * `PdfOrder` (заказ на генерацию PDF),
    * `BotDocument` (ответ с готовым PDF),
    * `TextItem`, `ImageItem` и других типов элементов сессии.
* Упростить эволюцию протокола (добавление `voice`, `document`, `location` и т.п.).

## Текущее состояние (вариант C)

* Есть идентичный модуль с моделями (Pydantic) в коде бота и в коде backend-а.
* Любое изменение формата требует **ручного** обновления двух копий.
* Это осознанный техдолг, который нужно закрыть до активного наращивания фич.

## План перехода на вариант A

1. **Создать отдельный репозиторий/пакет**, условно `pdfnik-contracts`:

    * Структура вида:

        * `pdfnik_contracts/__init__.py`
        * `pdfnik_contracts/orders.py` (модели заказов: `PdfOrder`, `Item`, `TextItem`, `ImageItem` и т.д.)
        * `pdfnik_contracts/documents.py` (ответы с PDF: `BotDocument` и т.п.)
    * Настроить `pyproject.toml` или `setup.py` для установки пакета.

2. **Перенести модели** из дублированных файлов в `pdfnik_contracts`:

    * Убедиться, что названия полей и типы совпадают с тем, что фактически уходит в RabbitMQ сейчас.
    * При необходимости добавить версионирование (например, поле `schema_version`).

3. **Подключить пакет в бот и backend**:

    * Внести пакет в `requirements.txt` / `pyproject.toml` обоих сервисов (временно можно ставить из Git-репозитория).
    * Заменить локальные импортируемые модели на:

        * `from pdfnik_contracts import PdfOrder, BotDocument, TextItem, ImageItem, ...`

4. **Удалить дублирующиеся определения моделей** из кодов бота и backend-а.

5. **Добавить простые проверки/тесты**, которые гарантируют:

    * что `PdfOrder.model_validate()` успешно валидирует данные, которые бот отправляет в RabbitMQ;
    * что `BotDocument.model_validate()` успешно валидирует данные, которые backend отправляет обратно.

## Критерии готовности (Definition of Done)

* В коде бота и backend-а **нет дублирующихся Pydantic-моделей**, все импортируются из общего пакета `pdfnik-contracts`.
* Все интеграционные цепочки работают:

    * бот → `orders` → backend → `bot_documents` → бот.
* Изменение формата (например, добавление нового типа `voice`) требует правок **только в одном месте** — в
  `pdfnik-contracts`.
* В репозитории есть краткая документация по контрактам (либо в самом `pdfnik-contracts`, либо ссылкой оттуда).
